Detailed Description

The client that connects to a server and plays the game.

A Client maintains the connection to a server (through a Socket) and the local Room where the game state is mirrored. It converges to a pure connection: the controller interface (requests / notifications / replies / speech / operation) lives on its own Agent (see Client::agent()), which a UI or an automated player drives.

The client's objectName is its playerName: the constructor assigns a random objectName, the self Agent is registered under that name, and the sign-in reports it to the server as the playerName. playerName is therefore not configurable by design, and the operation side must not rename the client (setObjectName()) while it is connected. Renaming desynchronizes the self Agent's objectName key from the sign-in playerName, so the server ends up tracking a different identity than the one the self Agent drives.

Stops the automatic reconnect loop and drops the underlying socket without going through the "connection lost" path, so no socketConnectionLost / socketErrorDisconnected signal is emitted (the caller already knows it disconnected). A later connectToHost() reconnects as a fresh session.

◆ agent() [1/2]

Agent * QMdmmNetworking::Client::agent ( )

get this client's own agent

Returns
this client's own agent

The client pre-creates its own Agent on construction (symmetric to the server side where the operation side creates the agent and hands it to LogicRunner). The operation side (GUI / Bot) drives the controller interface through it: incoming requests arrive on its xxxRequested signals, and replies / speech / operation are sent back by calling its bare-verb methods (rockPaperScissors / actionOrder / action / upgrade) and speak / operate.

The returned pointer is the stable handle stored by initSelfAgent(), not a lookup by objectName(). Renaming the client is forbidden (see the Client class doc); the stable handle is defense-in-depth so agent() never detaches even if that invariant is violated.
