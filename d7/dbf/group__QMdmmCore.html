Detailed Description

The game rules engine. Pure logic: it knows how a game of QMdmm is played, but not how players connect – QMdmm Networking library delegates every rule decision to what lives here.

Logic is the round state machine; drive it through its reply slots and it emits the request and result signals that move the round along. It works on a Room – a set of Player objects plus a LogicConfiguration, which holds the rules of the game (damage and HP ranges, the punish rule, the LetMove toggle, ...) and serializes to JSON. Data carries the enums and flags those types exchange, and Protocol the wire format: Packet plus the RequestId and NotifyId enums.

Nothing here is tied to a network, a user interface or a particular executable: Logic only emits signals and accepts slot calls, so a game can be driven with no connection at all. The transports live in QMdmm Networking library.

StateMaskTrust 

Mask of the "managed" flag.

The flag only travels: the operation side declares it, the server owns it and reports it back (see Protocol::NotifyManagedChanged). What being managed means below the wire is a client-side decision: a client that manages its player gives up on that player's requests instead of asking – answering each with the protocol's give-up marker, a null reply value – so the server answers each one with the default reply it keeps for that kind of request (see Protocol::RequestId). The managed player stays connected while that happens, and those default replies are broadcast like anyone else's.

Entrusting a player therefore changes who chooses, not whether anything happens. The upgrade point is the clearest case: the default reply there is an empty list, which the logic replaces with a fallback of its own (Logic::upgradeReply) that spends every point, knife damage first. A managed player goes through the upgrade phase and spends its points like anyone else.

A reconnecting player must NOT be re-trusted by default.

◆ RequestId

enum QMdmmCore::Protocol::RequestId : uint8_t

The IDs for requests and replies.

No requests come from the server; all requests originate from the Logic.

Enumerator
RequestInvalid 

An invalid request / reply.

RequestRockPaperScissors 

A request of Rock-Paper-Scissors.

Wire format – request: {"playerNames": [string], "strivedOrder": int} (a strivedOrder of 0 selects an action instead of a strived order); reply: int rps.

RequestActionOrder 

A request of action order.

Wire format – request: {"remainedOrders": [int], "maximumOrder": int, "selectionNum": int}; reply: [int] orders, one entry per selection (the reply length equals the request's selectionNum). Each entry is either 0 to yield that selection – the player accepts whatever order is left over and stops competing for it – or an order in the range 1..maximumOrder that the player strives for. A reply longer than selectionNum is rejected at the decode layer and disconnects the client. A well-formed reply that is not feasible (a length below selectionNum, an order outside 1..maximumOrder, or a duplicated / already confirmed order) is not rejected: it falls back to yielding every selection, so a buggy or malicious agent cannot stall the ActionOrder phase.

RequestAction 

A request of action.

Wire format – request: int currentOrder; reply: {"action": int(Action), "toPlayer": string (optional), "toPlace": int (optional)}. A reply whose action is not feasible (e.g. an unknown toPlayer or an unaffordable action) is not rejected: it falls back to DoNothing, so a buggy or malicious agent cannot stall the Action phase.

RequestUpgrade 

A request of upgrade.

Wire format – request: int remainingTimes; reply: [int] item. The request's remainingTimes carries the player's upgrade points for this round (the value of Player::upgradePoint – the wire name is a legacy mismatch, the rename is deferred to the v0 freeze); the reply must spend exactly that many points, so its length must equal remainingTimes. A reply longer than remainingTimes is rejected at the decode layer and disconnects the client. A well-formed reply that is not feasible (a length below remainingTimes, or an item whose stat has no upgrade points left) is not rejected: it falls back to spending every point in the order knife -> horse -> maxHp. An empty reply is a deliberate protocol value that triggers this same fallback, so a buggy or malicious agent cannot stall the Upgrade phase.

A notify from server of version number.

Wire format: {"versionNumber": string, "protocolVersion": int}.

When protocolVersion differs from Protocol::version() the client disconnects: the wire protocol is incompatible, so it drops the connection via disconnectFromHost() rather than entering the auto-reconnect loop (which would re-hit the same mismatch). Wire format: broadcast, object (see QMdmmCore::LogicConfiguration in qmdmmroom.h).

Keys absent from the object fall back to the receiver's own LogicConfiguration::defaults(), so a partial object – or an empty one, meaning "all defaults" – is accepted; a present key must still be valid, otherwise the receiver ignores the notify and keeps its previous configuration. NotifySignIn 

A notify to server of sign in.

Wire format: {"playerName": string, "screenName": string, "agentState": int (AgentState), "lastRoundEventSeq": int}.

agentState is a self-declaration: on a fresh sign-in the server stores it verbatim and does not filter or validate the StateMaskTrust / StateMaskBot flags. Trust ("managed") and Bot are client promises, not server-enforced privileges – the server never asserts either flag itself, only toggling the Online flag (cleared on disconnect, restored on reconnect) and clearing Trust on disconnect. A reconnect ignores the reported agentState and only restores the Online flag (Trust is not re-granted, see StateMaskTrust).

NotifyManagedChanged 

A notify to server of the player declaring its managed state.

Wire format: {"managed": bool}.

The player is identified by the socket, so no name is carried. Like the sign-in agentState (see NotifySignIn) this is a self-declaration: the server applies it to the StateMaskTrust flag, leaves the remaining flags alone, and reports the result back through the ordinary NotifyAgentStateChanged broadcast. It is the runtime counterpart of the managed flag a sign-in carries, for a client UI that toggles being managed while the connection is up.

A payload that is not an object, or whose managed is not a bool, is a protocol error: the server raises Socket::ProtocolError and drops the connection rather than ignoring the notify. The same happens on a socket that has not signed in – there is no player whose flag could be applied.

◆ PunishHpRoundStrategy

enum QMdmmCore::LogicConfiguration::PunishHpRoundStrategy : uint8_t

The round strategy of punishing HP.

Punish HP is taking place when a player slashes others in city. By default a half of maximum HP is lost.
Since HP is integer value one can not have a ".5" stuff or something, so rounding of the calculated half is needed. The modifier can be configured individually, so "a third" or "a quarter" etc. are also configurable

Currently there is 4 different rounding strategy supported. Following table is sort by understandability.

Strategy name Description Examples
LogicConfiguration::RoundDown Round all number down, i.e. digits after the dot are stripped. 1.1 -> 1, 1.4 -> 1, 1.5 -> 1, 1.9 -> 1, 2.0 -> 2
LogicConfiguration::PlusOne Apply +1 after round all number down. 1.1 -> 2, 1.4 -> 2, 1.5 -> 2, 1.9 -> 2, 2.0 -> 3
LogicConfiguration::RoundUp Round all number up, i.e. plus one if there are digits after the dot, then digits after the dot are stripped. 1.1 -> 2, 1.4 -> 2, 1.5 -> 2, 1.9 -> 2, 2.0 -> 2
LogicConfiguration::RoundToNearest45 Round all number to nearest integer. Round down if the first digit after dot is <= 4, round up else. 1.1 -> 1, 1.4 -> 1, 1.5 -> 2, 1.9 -> 2, 2.0 -> 2
Enumerator
RoundDown 

Round all number down, i.e. digits after the dot are stripped. See table above.

RoundToNearest45 

Round all number to nearest integer. Round down if the first digit after dot is <= 4, round up else. See table above.

RoundUp 

Round all number up, i.e. plus one if there are digits after the dot, then digits after the dot are stripped. See table above.

PlusOne 

Apply +1 after round all number down. See table above.
